# Kitapstore

Книжный магазин: React + Vite (`frontend`), Express + Mongoose (`backend`).
Этот этап исправляет основу запуска и совместимость существующих страниц;
он не завершает оплату, восстановление пароля или админку.

## Требования и установка

Используйте Node.js 22.12+ либо актуальную LTS 24 и npm. Проверено на Node 24.15.
Нужна запущенная MongoDB локально либо доступный кластер Atlas.

```bash
cd backend
npm ci
cp .env.example .env
cd ../frontend
npm ci
cp .env.example .env
```

Если `.env` уже существует, не перезаписывайте его: добавьте недостающие настройки
вручную. Реальные `.env` исключены из Git; `.env.example` можно коммитить.

## Настройки backend

Файл `backend/.env` загружается независимо от текущей папки запуска.

| Переменная | Назначение |
| --- | --- |
| `URI` | Обязательная строка MongoDB, например `mongodb://127.0.0.1:27017/kitapstore` |
| `JWT_SECRET` | Обязательный случайный секрет для подписи и проверки JWT |
| `PORT` | Порт API, по умолчанию `1001` |
| `FRONTEND_URL` | Точный origin frontend для CORS и OAuth, по умолчанию `http://localhost:5173` |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Необязательные настройки Google OAuth; без них обычный вход работает |
| `GOOGLE_CALLBACK_URL` | Callback Google, по умолчанию `http://localhost:1001/api/v1/user/auth/google/callback` |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASS` | Необязательный SMTP; порт `465` использует TLS, `587` — STARTTLS |
| `EMAIL_TO` | Получатель сообщений формы контактов и уведомлений о регистрации |

Секрет можно сгенерировать командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
и сохранить только в локальном окружении.

Для Atlas создайте пользователя базы, разрешите IP backend и скопируйте строку
из Connect → Drivers. Укажите имя базы `kitapstore` перед `?`, подставьте пароль
с URL-кодированием специальных символов. URI никогда не помещается во frontend.

При отсутствии `URI`/`JWT_SECRET`, некорректном порте или недоступной базе backend
завершается с кодом 1. HTTP-порт открывается только после подключения MongoDB.
Ошибка подключения не выводит URI и пароль.

## Настройки frontend

В `frontend/.env`: `VITE_API_URL=http://localhost:1001` — origin backend без `/api/v1`.
Все запросы используют `frontend/src/config/api.js`. Для reverse proxy с `/api`
на том же домене можно указать `VITE_API_URL=`. Перезапускайте Vite после изменения;
production-сборку нужно собрать заново. Переменные `VITE_*` публичны: секретов в них быть не должно.

## Запуск

В двух терминалах из корня проекта:

```bash
npm run dev --prefix backend
```

```bash
npm run dev --prefix frontend -- --host 127.0.0.1 --port 5173 --strictPort
```

Откройте `http://localhost:5173`. Проверка API: `http://localhost:1001/api/v1/test`
должна вернуть `API OK`. Если порт frontend изменён, согласуйте `FRONTEND_URL`.

## Совместимость и OAuth

Сохранены `/api/v1/<операция>` для книг и старых запросов корзины, избранного
и заказов. Также работают `/api/v1/books`, `/api/v1/cart`, `/api/v1/favourites`,
`/api/v1/orders` с прежними именами операций.

Google: начало входа `/api/v1/user/auth/google`, callback
`/api/v1/user/auth/google/callback`. Настройте в Google точный callback URL.
Без стратегии endpoint возвращает 503, а сервер продолжает работать.
Facebook пока не реализован: существующие endpoints отвечают 503 вместо ошибки Passport.
Аккаунты с существующим email автоматически не связываются с Google.

JWT выдаётся и проверяется единым модулем, срок — 7 дней. Старые токены без `id`
потребуют повторного входа. Заголовок `id` поддержан для совместимости, но должен
совпадать с подписанным идентификатором; при его отсутствии ID берётся из JWT.
Смена `JWT_SECRET` делает выданные токены недействительными.

Регистрация не зависит от SMTP. Если почта не настроена, уведомления пропускаются;
ошибка отправки не отменяет уже сохранённый аккаунт. Форма контактов требует SMTP.

## Проверки

```bash
npm test --prefix backend
npm run build --prefix frontend
npm run lint --prefix frontend
```

Backend-тесты используют фиктивные настройки и подменяют обращения к базе:
проверяют окружение, JWT, запуск после подключения, совместимость Mongoose,
регистрацию/вход без OAuth и почты, HTTP-маршруты и отключённые провайдеры.
Для HTTP-тестов необходимо разрешение слушать локальный порт.
Это не интеграционная проверка реальной MongoDB, SMTP или Google.

Для проверки реальной настройки запустите backend: сначала должно появиться
`Connected to Database`, затем `Server running on port ...`. После этого проверьте
API, регистрацию и вход через интерфейс. Для frontend-хостинга настройте SPA fallback
на `index.html`, чтобы прямые переходы на `/profile` и другие страницы работали.

## Следующие этапы и ограничения

- Завершить проверку данных регистрации, сессии, ограничения частоты запросов
  и серверную проверку прав на всех административных операциях.
- Доработать восстановление пароля: существующие endpoints ещё не образуют
  безопасный законченный сценарий; страница ForgotPassword пока пустая.
- Отдельно завершить удаление аккаунта и правила хранения связанных заказов.
- Исправить бизнес-логику заказов: текущий place-order некорректно обновляет
  корзину/историю; платёжного сценария нет. Этот этап её не меняет.
- Для платных PDF нужен закрытый доступ: текущие поля и API не подходят
  для защищённой выдачи файлов после оплаты.
- Google/SMTP проверяются после настройки внешних сервисов. OAuth пока использует
  существующий callback с токеном в URL; затем стоит перейти на одноразовый код
  или защищённую серверную сессию.
- В старых компонентах остаются предупреждения линтера о зависимостях useEffect.
