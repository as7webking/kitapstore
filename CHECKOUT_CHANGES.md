# Корзина и оформление заказа

## Исправления

Старый place-order создавал отдельные записи без цен и ошибочно дописывал
идентификаторы книг и заказов в user.cart. Новое оформление создаёт один заказ
с массивом позиций, очищает корзину и добавляет заказ в user.orders в одной
MongoDB-транзакции. Рабочая база не подключалась, миграции не запускались.

Сохранены flat и namespaced адреса API: /api/v1/place-order и
/api/v1/orders/place-order, существующие маршруты корзины/истории/статусов.
Старое тело { order: [{ _id, ... }] } поддерживается: поля цены, user и итогов
игнорируются. Новая форма отправляет только _id и quantity плюс Idempotency-Key.
Ошибки получают стабильные коды с переводами en/de/qt/ru.

Проверяются реальная сессия и её версия внутри транзакции, роль покупателя,
соответствие запроса всей сохранённой корзине, валидные уникальные ObjectId,
непустой адрес, существование книги, isDeleted, тип, PDF у цифровой книги,
цена и доставка. Физические экземпляры: целое количество 1–99; цифровой — 1.
Текущий UI, как прежде, покупает по одному экземпляру; API проверяет quantity.
Складских остатков в модели нет: реальный stock/reservation не реализован.

Цены берутся только из Book. Арифметика — целые евроценты; отрицательные,
нечисловые, слишком большие цены и значения с точностью больше двух знаков
отклоняются. Валюта остаётся EUR. Доставка из shippingPrice начисляется
за каждый физический экземпляр; цифровым — 0. Это текущая явная модель
расчёта, не интеграция с перевозчиком/налогами. Предварительная сумма в корзине
информационная: окончательная сумма и цены определяются каталогом в транзакции.
Настоящей оплаты нет, Order Placed не означает Paid.

Заказ хранит название, автора, описание, язык и тип книги, количество,
цену за единицу, доставку, сумму строки, subtotal/shippingTotal/total в центах,
адрес покупателя и валюту. PDF/пароль/токен не копируются. Редактирование или
удаление книги после оформления не меняет сохранённые данные нового заказа.
История возвращает совместимые строки с .book, но для новых заказов это
снимок данных. Каждая строка содержит lineId, количество и сумму строки;
статус принадлежит всему заказу. Ссылка на каталог может перестать работать
после изменения slug/удаления книги, однако состав и цена заказа сохраняются.
Старые заказы без снимка читаются через прежние данные каталога; восстановить
их исторические цены достоверно невозможно. Они помечены legacy в API.

Административный список больше не загружает пароль и recovery-поля пользователя.
Исправлен enum статусов и валидация изменения статуса; обычному пользователю
административные маршруты недоступны. Новые формулировки qt требуют вычитки
носителем, особенно описания доставки и конфликтов попытки оформления.

## Защита от повторного запроса

Идемпотентный ключ scoped по user: уникальный partial index
{ user: 1, idempotencyKey: 1 }. Checkout ждёт Order.init(), чтобы индекс был
готов. Ключ — 16–128 символов [A-Za-z0-9_-]. Тот же ключ и состав возвращают
созданный заказ; тот же ключ с другим количеством/составом даёт 409.
Новый ключ при уже очищенной корзине не создаёт второй заказ.
Транзакционные конфликты обрабатывает Mongoose transaction/драйвер.

Для старого клиента без ключа используется версия корзины + хеш состава.
Повтор последнего оформления пустой корзины восстанавливает предыдущий ответ,
а новая реальная покупка такой же книги остаётся возможна.
В корзину книга добавляется атомарным addToSet, а не через read/push.

Кнопка — настоящий button, состояние pending и синхронный ref блокируют повтор.
Ключ сохраняется в sessionStorage отдельно для пользователя и состава корзины,
поэтому обычный сетевой повтор/перезагрузка сохраняет идентификатор попытки.
При заблокированном storage ключ сохраняется только в памяти компонента;
повтор после полной перезагрузки может показать пустую корзину, но не должен
создать второй заказ. После успеха ключ удаляется. Изменение состава даёт новый.

## Требования к тестовому размещению

Нужна MongoDB replica set/sharded deployment с поддержкой транзакций (Atlas).
Standalone MongoDB не поддерживается для checkout: возвращается 503, нет
небезопасного последовательного fallback. Нужны права создания индекса
на тестовой базе. Старые документы без idempotencyKey не участвуют в partial
индексе. Не отключать unique index и не удалять существующие данные ради старта.

До внешней публикации проверить на отдельной kitapstore_test:

1. Успешное создание индекса и checkout из двух книг.
2. Один заказ/пустая корзина после двух одновременных одинаковых запросов.
3. Два разных ключа для одной корзины: только один новый заказ.
4. Потерю HTTP-ответа и повтор с тем же ключом.
5. Изменение цены/названия и soft-delete после оформления: история не меняется.
6. Реальный rollback при ошибке обновления пользователя и transaction retry.

## Выполненные проверки

- backend: 21/21 тестов, включая авторизацию, фальшивую цену/итог,
  некорректные количества и идентификаторы, недоступную книгу, ошибку записи,
  откат, одинаковые/разные ключи параллельно, legacy-повторы, повторную
  настоящую покупку, атомарное добавление в корзину и приватность истории.
- frontend: 16/16, включая ключ попытки, область пользователя/корзины,
  запрет пересылки цен, сумму доставки и полноту переводов/параметров.
- production build успешно; линтер: 0 ошибок, 8 прежних предупреждений hooks.
  Остались предупреждения о размере JS (~510 kB) и возрасте browser databases.
- Изолированный браузер, 320 px, немецкий язык, подменённый Axios:
  сумма 10,25 + 2,50 = 12,75 EUR; двойное нажатие отправило один запрос,
  показаны pending/disabled. Сценарий не создавал реальных заказов.
  Временные файлы браузерной формы удалены.

Установленного локального mongod нет. Реальная MongoDB/replica set не запускалась;
mock транзакции имитирует serial commit/rollback и не доказывает поведение
драйвера на живом кластере. Письма, платежи, deployment и push не выполнялись.
