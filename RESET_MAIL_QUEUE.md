# Durable password recovery email queue

## Что изменилось

API больше не отправляет письмо восстановления и не запускает его через void
Promise. Перед ответом 202 API ждёт commit MongoDB-транзакции: хеш нового токена
и задача outbox сохраняются вместе. Ошибка commit не оставляет токен без задачи
или задачу без токена. Нужна MongoDB replica set/sharded deployment с транзакциями,
как и для checkout. Standalone не получает небезопасный последовательный fallback.

Коллекция resetmailjobs создаётся моделью ResetMailJob. Для любого корректного
email создаётся задача, в том числе для неизвестного аккаунта. Неизвестная задача
не отправляется: worker завершает её без SMTP. Это сохраняет одинаковые 202,
message и PASSWORD_RESET_REQUESTED; ошибка хранилища возвращает одинаковый 503.
Невалидный email и общие rate limits работают как прежде. HTTP-ответ не зависит
от SMTP и не подтверждает доставку. Обычный вход/регистрация не требуют ключа
очереди; без него восстановление безопасно недоступно.

При повторном запросе старые pending/processing задачи отменяются той же
транзакцией, их зашифрованные данные удаляются, а хеш пользователя заменяется.
Рабочие данные в этом этапе не подключались, старые записи не мигрировались.

## Worker и повторы

Отдельная команда из корня репозитория:

```sh
npm run worker:reset-mail --prefix backend
```

API запускается отдельно через npm start --prefix backend. Worker не слушает
HTTP-порт. Каждый процесс обрабатывает по одной задаче, несколько процессов
разделяют очередь через атомарный findOneAndUpdate.

- Максимум 3 попытки получения задачи, способные начать SMTP. Брошенный lease
  тоже расходует попытку; четвёртый захват лишь завершает задачу как dead.
- Повтор после ошибки SMTP — через 30, затем 60 секунд. Deadline токена никогда
  не переносится. В письмо включается точный срок действия в UTC на en/de/qt/ru,
  а не новый полный интервал с момента отправки.
- Lease 5 минут, продление каждые 30 секунд; уникальный leaseId защищает записи
  от запоздалого worker. При SIGTERM/SIGINT worker прекращает брать новые задачи,
  ждёт текущую и отключает MongoDB. При аварии задачу заберёт другой процесс
  после истечения lease. SMTP сохраняет ограниченные connection/greeting/socket
  timeouts из существующего транспорта; это idle timeouts, не абсолютный срок.
- Перед расшифровкой и отправкой проверяются expiry, принадлежность lease,
  актуальный хеш токена, тип аккаунта, наличие пароля и неизменность email.
  Есть повторная проверка непосредственно перед вызовом SMTP. При остатке
  срока не более 30 секунд отправка не начинается. Использованные, заменённые,
  просроченные или удалённые аккаунты/задачи не отправляются.
- Успех сохраняет hash пользователя для последующего сброса пароля. При
  окончательной неудаче он очищается только условием resetPasswordTokenHash
  равен хешу этой задачи. Ошибка старой задачи не затрагивает новый токен.
  Если очистка пользователя не удалась после завершения задачи, expiry всё
  равно делает старый токен недействительным; новый запрос заменит его.

Гарантия — at least once с ограничением попыток, не exactly once. Если SMTP
принял письмо, а процесс погиб до записи sent, возможен повтор той же ссылки.
Message-ID стабилен для задачи, но почтовый сервер не обязан дедуплицировать его.
Одноразовость сброса и отзыв сессий по-прежнему обеспечиваются сервером.

Также нельзя отозвать уже начатую SMTP-передачу. Если новый запрос/сброс/expiry
произошёл ПОСЛЕ последней проверки и начала SMTP, старое письмо может прийти,
но ссылка уже будет нерабочей. Не обещаем отмену принятого SMTP сообщения или
валидность ссылки в момент доставки. Проверки защищают очередь перед dispatch,
а не позволяют транзакционно управлять внешним почтовым сервером.

## Защита секретных данных и очистка

Новая переменная RESET_MAIL_ENCRYPTION_KEY обязательна для восстановления и
worker. Это отдельные 32 случайных байта в base64, одинаковые у API и worker.
Получить локально openssl rand -base64 32; не отправлять результат в чат/Git.
Не использовать JWT_SECRET. Backend .env.example содержит только пустое поле.
В Vercel frontend этот ключ НЕ добавлять. Для staging отдельный ключ.

Email и сырой токен в задаче зашифрованы AES-256-GCM с новым IV на каждую задачу
и AAD, привязанным к _id задачи. URL/тема/текст письма не хранятся; формируются
worker в памяти из проверенного FRONTEND_URL. Payload и tokenHash исключены
из обычных выборок модели, API чтения очереди нет. Worker выбирает их явно.
Ключ остаётся в секретах окружения, отдельно от MongoDB и её резервных копий.
Нужны TLS к базе, ограниченные права API/worker и доступ к SMTP/секретам только
операторам. Шифрование не защищает от захвата процесса вместе с его ключом.

Сырые токены по-прежнему не хранятся в User — только SHA-256 и expiry.
В очереди необходима временная обратимая копия, поэтому она зашифрована.
Активный ciphertext имеет deleteAt равный исходному expiry, максимум 120 минут.
При sent/dead/cancelled payload и tokenHash удаляются сразу; минимальная
метаинформация остаётся до 24 часов и удаляется TTL-индексом deleteAt.
Проход worker также снимает секреты просроченных задач, независимо от задержки TTL.

TTL не гарантирует физическое удаление точно в секунду deadline, особенно если
MongoDB/TTL monitor недоступен. Worker не расшифровывает и не отправляет expired
задачи. Проверить индекс TTL и его работу вручную в тестовой базе. Резервные
копии могут хранить ciphertext дольше: настроить срок хранения backup отдельно.
Не менять ключ на работающих процессах по одному: сначала остановить приём
восстановления, завершить/отменить pending задачи, затем согласованно обновить
оба процесса. Неправильный ключ завершит недешифруемые задачи как dead и удалит
их текущие токены. При компрометации ключа отозвать ожидающие токены и заменить ключ.

## Настройка отдельного тестового окружения

1. Использовать только тестовую Atlas kitapstore_test с поддержкой транзакций.
2. Задать API и worker одинаковые URI/MONGODB_DB_NAME, FRONTEND_URL,
   PASSWORD_RESET_TTL_MINUTES и RESET_MAIL_ENCRYPTION_KEY. Нужны права записи
   и создания индексов коллекции. Обычные EMAIL_* настроить только на тестовую почту.
3. Для APP_ENV=staging сохранить требования Ethereal, HTTPS и отдельной базы.
4. На Render создать отдельный Background Worker с тем же репозиторием/версией,
   Root Directory оставить корнем, Build npm ci --prefix backend,
   Start npm run worker:reset-mail --prefix backend, Node 24. Health HTTP-порт
   worker не нужен. Runtime validateEnv также требует JWT_SECRET и прочие общие
   настройки backend. Все секреты только в Render, не во frontend.
5. Добавить outbound CIDR И worker, И API в Network Access только тестового Atlas.
   У worker должен быть доступ к SMTP 587. Не создавать платный сервис без решения
   владельца. В этом этапе облачные ресурсы не создавались.
6. Сначала запустить worker и проверить его безопасное сообщение о старте,
   затем API. Выполнить восстановление через тестовый Ethereal inbox.
7. Проверить pending/retry/dead и TTL по метаданным, не раскрывая payload,
   hash, ссылок или текста письма в логах/скриншотах. При остановленном worker
   задачи остаются в MongoDB, но после expiry уже не отправляются.

Другие уведомления регистрации/контакта/удаления аккаунта пока используют прежнюю
отправку. Очередь охватывает только запрошенный сценарий восстановления.

## Проверки

Подменённые MongoDB-модели и SMTP проверяют:

- атомарный enqueue/rollback, нейтральные известный/неизвестный email и отказ БД;
- все 4 языка, fallback, точную дату expiry, шифрование, подмену ciphertext/AAD;
- retry новым экземпляром worker, повторную обработку, захват брошенного lease,
  исключительность двух worker, предел попыток и удаление секретов;
- просроченный, заменённый, использованный токен и неизвестный аккаунт;
- замену после расшифровки до SMTP и позднюю ошибку старой отправки;
- SMTP success с потерей подтверждения MongoDB и повтор с тем же Message-ID;
- безопасный отказ CLI без ключа до подключения к базе;
- прежние требования пароля, одноразовость, гонку сброса, отзыв сессий и лимиты.

Реальная MongoDB replica set, отдельный OS-process crash и реальные SMTP не
проверялись. Подмена имитирует commit/rollback; новый объект worker имитирует
перезапуск, а истёкший lease — аварийное завершение. Перед публикацией повторить
внешние проверки на отдельной базе и тестовой почте. Нельзя называть их пройденными.
Крымскотатарскую формулировку точного срока в accountEmail.js вычитать носителем.

Add a durable encrypted password reset email queue with a separate worker

Коммит, staging, push и deployment агентом не выполняются.
